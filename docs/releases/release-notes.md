## v0.3.0 - 2026-11-13

本版重点帮助修谱者发现资料问题，并减少导入、导出时对亲属关系的误读。

### 新增功能

- **资料体检**：家族协作者可在族谱工作区的「资料体检」页签集中检查 11 类问题：生卒年倒置、在世状态与去世资料矛盾、未来年份、关系引用缺失人物、自身关系、重复关系、未核实关系、父母与子女生年顺序异常、已确认世代不相邻、生物学父母超过两位，以及生物学亲子循环。
- **逐项核查**：提示区分错误、警告和信息，支持按严重程度、姓名筛选，分页查看、重新检查，并定位对应人物或关系。检查只提供线索，不自动改写资料、合并人物或认定血缘。

### 修复与改进

- **公开图谱隐私**：无权查看的生卒年不再出现在图谱数据中；「重复核对」和导入报告仅向家族协作者开放。
- **可靠导入**：同一导入任务并发提交时只执行一次写入；文件中人物标识重复时阻止导入，避免关系引用错人。JSON 中的监护、过继等关系不再被转换为生物学亲子。
- **GEDCOM 亲属关系**：导出时不会仅凭配偶关系为孩子增加父母；保留收养关系，避免一个子女的收养标记串用到其他子女。
- **GEDCOM 姓名与日期**：修正标准姓名顺序、日期中的日被误读为年份，以及「已故但卒年未知」状态在交换中丢失的问题。
- **图谱范围**：零层查看参数现在可正确生效，便于只查看所选人物。

### 升级与兼容说明

- 从 v0.2.2 升级无需新增数据库迁移。权限收紧后，非协作者需要先接受家族协作邀请，才能使用重复核对或查看导入报告。
- 外部 GEDCOM 的 `PEDI birth` 不直接作为生物学血缘证明；缺少明确子类型的关系保留为未知，需依据史料核实。本次修复不会自动纠正此前已导入的资料。
- GEDCOM 用于资料交换，不能完整表达本项目的全部关系信息。版本快照用于族谱恢复；完整实例备份仍需同时保存数据库和上传档案。

## v0.2.2 - 2026-11-13

本版加强自托管实例的更新包校验，并让管理员在安装前看清发布内容。

### 新增功能

- **发布包完整性校验**：稳定版更新使用项目专用 Release 发布包，安装前检查文件大小和 SHA-256。缺少受支持的发布包、缺少摘要或校验失败时拒绝安装。
- **可选数字签名验证**：实例可配置公钥验证发布包的独立签名；要求签名时，缺少公钥、签名缺失或验证失败均会阻止安装。
- **更完整的更新详情**：后台「系统设置 → 系统更新」展示发布资产名称、大小、SHA-256、更新性质及最低支持版本，便于决定升级安排。
- **标准发布附件**：发布流水线在检查通过后生成具名压缩包、SHA-256 校验文件与更新元数据，供管理员下载和更新器读取。

### 修复与改进

- 更新器不再在 Release 缺少受支持资产时回退安装未经过摘要校验的源码包；发布资产地址须属于配置的 GitHub 仓库并使用 HTTPS。
- 写请求校验完整来源地址，区分协议、主机与端口；格式异常的来源会被拒绝，避免仅比较主机带来的校验缺口。
- 新增「跳到主要内容」入口及主导航标签，键盘和辅助技术用户可更快进入页面内容。

### 升级与兼容说明

- 从 v0.2.1 升级无需新增数据库迁移；已有 SOURCE / DOCKER 部署继续使用相应驱动。
- 签名功能需要发布方提供 `.sig` 附件及对应公钥。截至 2026-11-13 整理日志时，v0.2.2、v0.3.0 的发布附件均未包含 `.sig`；配置公钥或启用强制签名的实例会拒绝这些未签名发布包。SHA-256 校验不等同于数字签名。
- 稳定版 Release 具备发布包完整性校验；开发用分支通道不具有同等保证。

## v0.2.1 - 2026-11-10

本版修复演示口令展示和测试数据残留问题，并补全项目使用资料。

### 修复与改进

- **登录页口令保护**：登录页不再公开演示账号密码，使用文档同步移除口令；需要开发演示账号时，可查阅项目的种子数据说明。
- **测试数据回收**：冒烟脚本结束时回收自己创建的族谱和社区帖子，避免公开族谱列表、社区信息流长期混入测试内容；涉及的族谱先转为私有，再软删除。
- **历史测试数据清理**：新增清理工具，可按约定名称前缀预览历史测试族谱与帖子，确认后执行软删除。
- **依赖维护**：更新 minimatch 依赖约束，修复该工具链依赖的已知问题。

### 文档与开源使用

- 项目首页重新梳理功能、快速启动、隐私边界和部署入口，补充英文说明及 19 张真实运行截图。
- 新增 MIT 许可证、贡献指南和安全问题私密报告说明；校准部署、API、用户手册与验收文档，清理不应入库的生成物和内部报告。

### 升级与兼容说明

- 从 v0.2.0 升级无需新增数据库迁移。页面隐藏口令不会更改已有账号密码；使用过演示种子数据的生产实例仍需自行处理演示账号。
- 历史测试数据不会随升级自动清除。先用 `pnpm test:cleanup` 预览候选记录，确认后再添加 `--apply`；清理采用软删除，避免直接销毁数据。

## v0.2.0 - 2026-11-10

本版加入在线维护入口，并扩展修谱时的统计、查重和检索能力。

### 新增功能

- **在线更新**：管理员在「系统设置 → 系统更新」检查上游版本、阅读日志并发起升级，查看备份、下载、校验、安装和重启进度。更新前默认备份数据库与上传档案，备份失败时中止。
- **部署适配与提醒**：支持源码部署、Docker 部署和演示驱动；管理员个人中心及后台显示新版本提示，关闭后按目标版本记忆，下一个版本发布时重新提醒。
- **家族统计**：族谱工作区展示成员数量、在世比例、性别构成、世代与年代分布、分支人数、字辈用字和资料核实情况，帮助识别资料覆盖情况。
- **疑似重复人物核对**：按姓名、字号和别名列出候选配对，提供三档置信度与判定依据，供修谱者逐项核对，不自动合并人物。
- **人物搜索扩展**：关键词可匹配姓氏、名、字号和别名；修复只输入姓氏时找不到人物的问题。

### 修复与改进

- 修复更新任务在备份、下载或较长构建期间被误判超时，以及分支版本提交号格式不同导致成功状态无法确认的问题。
- 改善 Docker 更新等待、超时收尾和任务锁释放；另一位管理员发起新任务后，更新面板可跟随当前任务。
- 公开统计遵循在世人物隐私设置；运行期上传档案不再被构建追踪并带入应用构建产物。
- 重复核对增加规模限制，避免大族谱中配对数量过大；工作区页签支持换行和直接定位链接。
- 更新 Next.js、TypeScript 等基础依赖，适配新版校验库；发布流程可根据版本日志自动生成 GitHub Release。

### 升级与兼容说明

- 从 v0.1.0 基线升级需要执行数据库迁移，新增更新任务表和人物姓氏搜索索引。部署前备份数据库及上传档案，按部署指南执行 `pnpm db:migrate` 并重新构建。
- 源码部署需配置进程守护与重启方式；Docker 部署需配置 updater 服务。演示驱动不会安装新版本，不能作为生产升级验证。
- 本版发布时的记录未证明真实 SOURCE / DOCKER 跨版本升级全流程已验收，部署者需在自己的预发环境核对备份、重启和新版本健康状态。

## v0.1.0

初始功能基线，保留历史记录，不补记未经确认的发布日期。对应仓库首次提交中的 `0.1.0` 版本，未单独发布 Git 标签或 GitHub Release。

### 姓氏与寻根

- 收录《百家姓》504 姓的字形、读音、序位及单姓/复姓类别；有来源的条目提供源流、郡望堂号、历史人物与迁徙线索，资料不足的条目标明待补录。
- 史料带来源引用、可信程度与审核状态；历史人物、姓氏资料和用户真实家族关系独立保存，不因同姓或同名自动认定同宗。

### 族谱与协作

- 创建族谱、维护人物与亲属关系，管理字辈、世代、分支和祖籍信息；提供关系冲突检查、祖先/后代追溯与亲属称谓计算。
- 提供纵向世代树、横向世代树、分支折叠与时间轴视图，支持缩放、搜索定位和关系路径查看。
- 提供所有者、编辑者和查看者协作权限，支持邀请、可见范围设置、删除恢复与版本快照。

### 资料保存与交流

- 支持 GEDCOM、CSV、JSON 导入预览，确认后写入；提供 JSON、CSV、GEDCOM 5.5.1 / 7.0、SVG、PNG、PDF 导出。图像和 PDF 用于展示，不是可回导的完整备份格式。
- 档案中心管理谱页与文献；宗亲社区提供交流、寻亲、评论、纠错和通知，同宗关联需双方确认。
- 管理后台提供内容管理和审计，配套数据库与上传档案备份、Docker/Nginx 部署配置。

### 使用边界

- 导入的关系需人工核实；版本快照和交换文件不包含全部敏感字段，完整实例恢复依赖数据库及档案备份。
- 外部 OCR、对象存储等服务需按部署环境配置，不代表初始版本已替使用者接入外部服务。
