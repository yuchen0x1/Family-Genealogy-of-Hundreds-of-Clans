# v0.3.0 发布前验证（2026-11-13）

## 1. 总览

本次发布包含资料体检、隐私边界与导入/GEDCOM 修复，无新依赖和数据库迁移。版本准备后，`pnpm test` 239 项通过 / 21 项跳过，`pnpm lint` 与 `pnpm build` 通过。跳过项包括 17 项 POSIX shell 相关测试和 4 项需显式开启独立 PostgreSQL 的集成测试；这 4 项在功能开发阶段已在独立库实际通过，详见 [首次本地验证](../EVOLUTION_2026-11-13.md)。

Web 暴露扫描针对最终 `.next/static` 的 33 个文件（32 个 Web 产物），扫描器返回 100/100、A、0 findings。该分数只代表静态规则未命中，不是完整安全保证。项目本来就是 MIT 开源，源码公开属于产品设计，不把代码可读性当作漏洞。

## 3. 逐项证据与修复

- 使用安装的 `reverse-engineering-exposure-audit/scripts/exposure_scan.py`，通过 `python -I` 只读扫描最终客户端产物。原始结果保存在本地忽略目录 `.autonomous-upgrade/release-v0.3.0-exposure.json`。
- 对生产构建所有 `.nft.json` 的 files 数组检查敏感目录引用，95 份、0 命中；Git 受跟踪文件也未包含 `.env`、本地数据库、上传目录或备份目录。
- `src/lib/auth.ts` 从 HttpOnly Cookie 恢复会话，并查询服务端会话记录；`permissions.ts` 根据服务端家族归属与协作状态判断权限。新增体检、重复核对、导入报告接口使用服务端协作者校验，不能仅通过显示前端按钮获得访问权限。
- 本轮静态扫描没有需要新增混淆或加壳来处理的发现；保留现有开源结构。

## 4. 客户端无法解决的问题

- 家族权限与会话的最终判定必须留在服务端；前端隐藏操作只是交互，不能替代鉴权。本次实现保持这条边界。
- 更新包 SHA-256 用于完整性检查，不能单独证明发布者身份。现有更新器支持公钥校验分离签名；发布流水线只有配置签名私钥时才产出 `.sig`，本轮不创建或输出签名密钥。是否有签名需以实际 Release 资产为准。
- 本报告不证明线上会话、部署配置或真实客户端更新链路已验收。前一阶段启动本机测试站点遭自动审批拒绝，因此没有新增页面截图或本轮浏览器端到端通过结论。依赖 advisory 查询也未成功。

## 5. 修复顺序

1. P0：已修复并测试的公开年代/内部报告泄漏与导入重复写入随本版本交付；静态客户端扫描未发现需紧急处理的凭证。
2. P1：发布依赖 GitHub Actions 的 quality 与 smoke 检查成功后创建 Release；检查下载包、校验文件和更新元数据存在且匹配。CI 结果以对应提交的 Actions 页面为准。
3. P2：补新页面桌面/移动浏览器验收、可用依赖漏洞查询与动态存储 tracing 改进。发布后的老客户端实际升级仍需单独验证。
