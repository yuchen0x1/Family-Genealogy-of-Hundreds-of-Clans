# v0.4.4 审计与验收

日期：2026-11-27（北京时间）。本次为安全及稳定性补丁，没有新增数据库迁移。

## 修复范围

- 人物 PATCH 省略字段保留原值，核实状态贯通表单、schema 和创建接口。
- 邀请替换、撤销、权限变化后旧 token 失效；接受邀请事务内单次领取，拒绝已删除家族。
- 关系详情统一内部字段边界，公开档案限制历史版本访问，上传数据库失败清理孤儿文件。
- 恢复人物避免连接仍已删除人物的悬挂关系。
- 登录、退出及撤销当前会话刷新身份缓存，登录注册保留合法站内返回地址。
- SOURCE 更新构建后执行迁移，迁移失败恢复运行文件并提示数据库检查；稳定 tag 筛选、预发布版本排序和校验清单匹配修复。
- 备份保留参数严格验证、普通账号恢复与外键循环修复；PostgreSQL 引导连接正确关闭。
- `glob` 更新到 14.0.2，CI 与每周审计覆盖生产、开发依赖。

## 本地证据

- Node.js 22.23.5、pnpm 11.20.0、Next.js 16.4.6；lint、类型检查、生产构建通过。
- 隔离 PostgreSQL 17.11（127.0.0.1:55439）应用全部 6 个迁移并初始化测试数据；未使用现有实例的数据库。
- Vitest 293 passed / 17 skipped。17 项为 Windows 缺少 POSIX shell 的 sidecar 测试，Linux CI 负责补验。
- 新增真实数据库用例验证人物恢复边界、邀请并发领取、撤销、重新邀请降权和删除家族。
- 安装脚本子进程夹具验证构建、迁移顺序及迁移失败的源码、依赖、构建回滚。
- 备份测试 15/15 通过。真实 PostgreSQL 普通角色（NOSUPERUSER / NOREPLICATION）独立双库完成 CLI 备份、校验、恢复：48 张表、12 行、1 个上传文件逐字段一致；覆盖反序父子记录、双表循环、空表、坏外键整体回滚和非空目标拒绝。测试后核实临时角色、双库和文件均已清理。
- `pnpm audit --registry=https://registry.npmjs.org --audit-level low` 无已知漏洞。
- 本机测试服务器启动被自动审批规则拒绝（blocked by policy），本地没有完成 HTTP/浏览器验证；发布 CI 会运行 HTTP、安全审计、Chromium 桌面/移动与 Docker 构建启动门禁，通过后才公开 Release。

## 仓库卫生

审计开始时本地工作区干净，远程只有 main，没有开放 Issue、PR 或 Dependabot 告警。追踪文件未发现可确认的缓存、真实环境配置、数据库、上传数据、私钥或重复内容。历史审计文档与 README 图片仍被文档引用，予以保留。

Release 从 Git 提交归档，本地 node_modules、.next、.storage、reports 不进入源码发布包。缓存清理限于项目生成物和本次隔离测试目录；不删除数据库、上传档案、备份、凭据或全局依赖存储。

Code Scanning API 没有可用分析结果，未宣称通过 CodeQL 或完整第三方安全审计。Secret Scanning 无可见开放告警，但功能及令牌权限范围限制其结论。

## 升级边界

旧 SOURCE 实例首次安装本版仍运行自己的旧脚本。本版没有新迁移，迁移步骤修复在本版安装后的下一次升级生效。文件回滚不会撤销已经应用的数据库迁移。

没有进行真实生产实例的 SOURCE / DOCKER 跨版本升级、外部 OCR/S3 或生产签名私钥演练。自托管环境仍需备份数据库及上传档案，在预发验证后升级。

旧逻辑备份可能已经将无时区时间字段转换为 ISO 时间，无法从文件可靠推断原始时区。新版保留 timestamp/date 原始文本；旧文件跨时区恢复前仍需核查。
