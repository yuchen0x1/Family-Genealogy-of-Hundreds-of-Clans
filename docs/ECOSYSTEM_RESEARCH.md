## 重点对比与本轮取舍

| 能力 | 对照 | 当前实现及差距 | 决策 |
| --- | --- | --- | --- |
| 平台覆盖 | Gramps 提供桌面核心，Gramps Web 独立部署。Progenies 将安装入口与自托管 Web 结合。 | 本项目需要中心服务做权限判断和 GEDCOM 工作流，重建多套客户端的成本高。 | 首选移动/桌面浏览器和 PWA。桌面原生、商店客户端与扩展延后。 |
| 导航与关系研究 | Gramps 的树、事件、来源有各自视图。webtrees 以多树管理与隐私开关组织用户工作。 | 已有多视图、亲属关系与专有中文历史数据。工作区可继续增强证据、冲突与键盘导航。 | 保持品牌和现有导航，后续优先细化研究视图。 |
| 数据交换 | FamilySearch 规范结合 gedcom-go 和 gedcom-lite 的格式边界。 | 现有 GEDCOM 5.5.1/7、CSV、JSON，未知标记与遗留编码的保真仍有空间。 | 增补多来源样本，保留来源和未核实语义。 |
| 客户端缓存 | Workbox 的预缓存与运行时策略可独立部署。 | 私有族谱、下载、会话跨用户缓存会增加数据泄漏和恢复难度。 | 本轮实现最小离线提示，推迟可持久化的编辑队列。 |
| 自托管与来源 | Gramps Web 的 Docker 与 HTTPS 指南、webtrees-docker 多架构交付、Sigstore 的来源证明。 | 当前有源码与容器两条更新通道。原流水线先发布再附资产，容易出现短暂空包。 | 草稿上传后验完整性，签发构建证明，CI 验证 Linux x64 冷启动。 |

近期样本包括 Gramps Web v26.11.2、GEDCOM v7.0.18、Compose v5.8.0 和 cosign v3.1.4。具体改动以表内 Release 链接为准。30/90/180 天活跃度可由最近提交日期推断是否有近期活动，跨期频次与问题热度需另查历史事件。未引入第三方项目代码。下一轮对照问题以 [升级候选](../UPGRADE_ROADMAP.md) 为准。
